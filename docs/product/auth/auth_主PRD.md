## 0. 威胁与门禁

| ID | 威胁 | 要挡住的结果 |
|----|------|----------------|
| T1 | 撞库 | 泄露口令不能无限制重放 |
| T2 | 喷洒 | 少量口令打大量标识时，账号维和 IP 维都限住 |
| T3 | 枚举 | 登录、找回、以及「未证实口令」的禁用，不能用 HTTP 状态、`code` 或正文区分标识在不在 |
| T4 | 会话窃取 / 重放 | 退出、禁用、改密、重置之后，旧 token 不能只靠浏览器删除失效 |
| T5 | CSRF | 认证不靠浏览器自动带上的 cookie |
| T6 | XSS | 口令、验证码、注册 token 原文不进日志和 URL 查询串 |
| T7 | 验证码滥用 | 次数、有效期、单次消费、重发间隔 |
| T8 | 重置接管 | 没有绑定当前邮箱版本的验证证据，就不发重置凭证 |
| T9 | 跨租户 | 请求头不能把已登录会话授进另一个租户 |
| T10 | 并发 | 同一邮箱同时注册只建成一个账号；重置与发新会话不能留下旧 token |
| T11 | 通知洪泛 | 重发有间隔和日上限 |

上线某期前：该期「上线阻断」已满足；第 9 节对应场景须在实现交付中用准备数据跑过（本需求文档本身不代替这些验收）；第 5 节禁止项成立；未决项没有被实现者自行选边。

## 1. 范围

端：首期只承诺现有 Web 管理后台和它的 HTTP API。App、小程序以后可以复用 API，本期不承诺已经共用。

| 流程 | 首期目标 | 后续 | 上线阻断 |
|------|----------|------|----------|
| 注册 | 保持不填用户名、不自动登录。邮箱注册统一受理、不暴露是否已注册（D-EMAIL 已确认）。链接形态等 D-LINK | 无 | 邮件复用统一通知服务 |
| 密码登录 | 第 4 节的统一失败策略和锁定数值 | 无 | 匿名租户定位未决前，不改「非 0 租户账号怎么登录」（D-LOGIN-TENANT）。禁止把「全部匿名登录固定租户 0」当成无依赖的首期 |
| 退出 | 服务端吊销当前 token，后续 API 必须拒绝 | 无 | 无 |
| 改密 | 验原密码、拒相同新密码、成功后全部会话失效。接口为 `PATCH /user/profile/password`，旧新密码仍经既有 RSA 解密 | 不取消这条 RSA | 无 |
| 找回 | 本期不对外上线 | 验证码重置 | 没有第 2.5 节的验证证据就不得发凭证 |
| 会话 | 沿用并保持第 4 节所列有效期与并发参数。吊销失败时用凭证版本把门（拟定机制，见 3.4） | 记住我单独做，不假装已有 | 无 |

本期不扩建、也不删除已有入口：`GET /oauth/{provider}` 与 `grantType=OAUTH`；`grantType=OTP` 与 `POST auth/otp`。MFA、企业 SSO、生物识别本期不做，预留扩展点。

## 2. 身份与凭证

### 2.1 字段

| 概念 | 本 PRD 目标 |
|------|-------------|
| 登录名 | 不删除、注册页不填。租户内唯一，最长 64。存量短于 4 位的用户名仍可用于登录。管理端重名仍是「用户名已被占用」 |
| 邮箱 | 不改成全局唯一，不默认忽略大小写。邮箱规范化只做 trim，不改大小写。接口明文长度上限沿用 64，本期不改。`User@a.com` 与 `user@a.com` 视为不同标识 |
| 手机 | 本期注册不新增。存量兼容，仍可作登录标识，并保持租户内唯一 |
| 口令 | 见 2.3。只存慢哈希 |
| 注册 token | 只存哈希（SHA-256）。原文不得进入日志或 URL 查询串。邮件中的携带形态见 D-LINK |
| 失败次数 | 继续短期存储，不写入用户档案的持久字段 |
| 邮箱归属证明 | 拟新增，旧数据默认未验证。见 2.5。本期先定规则，具体持久化方案另行设计 |

确认前不创建可登录用户。

### 2.2 状态

持久账号状态与锁定叠加状态分开。用户持久状态沿用既有「正常 / 禁用」取值，不在本期改枚举含义。

| 状态 | 新的口令登录 | 已发出的 token |
|------|----------------|----------------|
| 待验证 | 不能登录 | 无 |
| 正常 | 还要过锁定与口令 | 有效直到过期、空闲冻结或吊销 |
| 禁用 | 见第 4 节：口令未证实前与「不存在 / 错密码」同一响应；口令已证实后才可返回禁用 | 已有 token 下一次 API 为 401 |
| 临时锁 | 锁定期内正确口令也拒绝，且不再为了展示状态多做一次「口令是否正确」的分支 | 不踢锁定期之前已经登录的会话 |
| 注销 | 不能登录。本期不单列自助注销产品流程；删除用户时会话必须失效 | 必须失效 |

### 2.3 口令

口令须用成熟的慢哈希组件存储，不自造哈希算法。拟定如下：

- 首期口令长度 8–32，以 UTF-16 代码单元计数；至少包含一个小写字母和一个数字。特殊字符要求由公开密码策略开关决定。不改成 8–64。放宽时须同步调整登录、注册、改密、重置规则与文案。
- BCrypt cost 维持 10。不在本期升到 12。
- BCrypt 只用 UTF-8 前 72 字节。哈希前若字节长度大于 72，拒绝，错误与格式错误同一类，不截断后再存储。32 个字符若含多字节字符，仍可能超过 72 字节，所以字符门代替不了字节门。
- 弱口令词表本期不做。常见口令仍可能通过「小写 + 数字 + 长度」门，只能靠锁定和喷洒限制补。至少拒绝：trim 后、忽略大小写，口令等于用户名，或等于邮箱 `@` 前的本地部分。该完整规则覆盖注册、改密与（若上线）重置，不能只在分配用户名时做部分检查。

### 2.4 邮箱比较

邮箱规范化只做 trim，不改大小写。不改成全库一个邮箱，仍按租户内唯一。比较与查重必须对规范化后的明文标识一致，不能靠忽略大小写合并账号。

### 2.5 找回用的验证证据

禁止把下列任何一项当成「可以发重置凭证」：

- 用户邮箱非空
- 账号曾经被创建（含后台建号、邀请建号、社交建号）
- 待验证注册申请还在
- 只改过邮箱值、但没有留下可核验证据

允许发重置凭证的唯一条件：存在一条可持久核对的邮箱归属证明，同时满足：

- 能实际核验，不能只是口头或文档声明
- 绑定当前用户标识
- 绑定当前邮箱明文的规范化值
- 绑定该邮箱的邮箱版本

要求达到：证明与当前用户标识、当前规范化邮箱、当前邮箱版本一并绑定，缺一不可。拟定机制为：邮箱版本从 1 起，每次邮箱值变化加 1；归属证明记录用户标识、邮箱版本、证据类型与完成时间。旧数据没有这条证明，一律视为未验证。具体持久化方案另行设计。

证据类型只承认两种：注册确认成功，且写入的就是这个邮箱版本；或者改邮箱时验证码校验成功，且写入的就是这个新版本。只改邮箱值、没有完成归属验证的，不算。

缺证据：不调用发信，对外仍是找回的通用受理响应。D-RESET-PROOF 仍待确认，只决定产品是否接受这道门；本 PRD 拒绝把「无证据也发信」写成可执行默认或并列实施指令。找回本身本期不对外上线，P3 在该决定未接受前不做。

## 3. 流程

### 3.1 注册

前置：公开注册开关开启；能解析默认普通角色。D-ROLE 未决前，确认建号时继续按既有规则写入默认部门与默认普通角色，本期不改为零角色或空部门。

步骤：

1. `POST /auth/register`，字段仅 `email`、`password`。
2. trim 邮箱；口令按 8–32 门，再加上 72 字节门。
3. 对可创建的新申请：分配用户名并写入待验证注册（口令只存慢哈希，注册 token 只存哈希）。写入成功后异步投递邮件，复用统一通知服务。已注册、冷却、额度命中或投递失败不改变对外统一受理，内部审计区分原因；不得向已注册邮箱重复创建用户，也不得绕过既有发信限额。
4. 确认接口要求在 POST body 提交验证秘密。若 D-LINK 选择 fragment 方案，邮件链接仅用于打开页面，秘密放在 fragment，不放 URL 查询串；确认请求的 body 字段仍为 `token`。若选择验证码方案，秘密只放 body，不进 URL。
5. 用户在页面上再调用 `POST /auth/register/verify`。不要在打开链接时自动调用。
6. 成功创建一个可登录用户，待验证申请标记为已消费。响应无登录 token。

成功（D-EMAIL 已确认）：HTTP 200，`code=200`，`status=ACCEPTED`，文案「注册申请已受理。如该邮箱可用于注册，你将收到验证邮件。」不返回 token。禁止用 `delivered`、`PENDING`、`COOLDOWN` 或其他仅部分分支才出现的字段做状态探测。`resendAfterSeconds`、`expiresMinutes` 如前端必须使用，按公开策略给固定值，不返回真实记录剩余时间。

对外可区分的失败，仅限不暴露该邮箱是否已注册的条件：

| 条件 | 对外 |
|------|------|
| 注册关闭 | 可返回明确错误（`REGISTRATION_DISABLED` / 系统未开放注册） |
| 邮箱格式 | `EMAIL_INVALID` |
| 口令不符合门 | `USER_PASSWORD_FORMAT_INVALID` |
| 账号查找前统一执行的 IP 限流 | 明确限流错误；同一条件不因邮箱是否存在而改变 |

已注册、无待验证申请、邮箱冷却或额度命中、邮件投递失败：与可受理申请同一 HTTP 状态、业务码、文案和字段形态（即上列统一受理）。禁止通过 `EMAIL_EXISTS`、`REGISTER_NOTHING_TO_RESEND`、`REGISTER_MAIL_UNSENT` 对外暴露。重发接口使用同一套统一受理规则。

确认环节：链接空、过期、找不到，对外为 `REGISTER_LINK_INVALID` / 「链接无效或已过期」。已消费，或确认时邮箱已有账号，结果 `ALREADY_VERIFIED`，不建第二个用户。

本 PRD：未确认不能登录。不自动登录。找回不得向待验证地址发重置凭证。

### 3.2 密码登录

前置：请求带 `clientId`。按既有字段优先级，从 `username`、`email`、`phone` 取第一个非空，加 `password`。图形验证码字段仅当该主体的失败计数达到阈值。租户定位见第 6 节，定位之后才做凭证校验，成员校验再分开。匿名登录的租户定位在 D-LOGIN-TENANT 未决前不改，禁止先改成固定租户 0。

步骤：

1. 规范化标识，按 HMAC 计算主体标识（输入须包含用途「登录」、当时定位到的租户标识、以及该登录标识）。不存在的标识用同一个 HMAC 规则，称为虚拟主体。
2. 若该主体处于锁定期：直接返回锁定响应，不再分支比较口令是否正确。因此锁定期内正确口令也被拒绝，且不会多一次「口令对不对」的对外差别。
3. 若计数已到图形验证码门：缺码或错码返回 `NEED_CAPTCHA`。这道门只看尝试计数，真实主体和虚拟主体共用。
4. 查当前定位租户内的用户。找不到：仍做一次结果丢弃的 BCrypt 比较，计数加 1，返回通用失败。
5. 找到：BCrypt 比较。不对：计数加 1，通用失败。对且账号禁用：这时才返回禁用（口令已证实，不能当廉价探测）。对且可用：清该主体失败计数，签发 token。

成功响应是唯一允许携带会话 token 的地方，见第 5 节。

### 3.3 退出

前置：有效登录。

步骤：`POST /auth/logout`。由会话服务在服务端吊销当前 token。只删前端存储不算退出。

成功：无 body 要求。该 token 再访问需登录接口为 HTTP 401，业务 `code` 为 `UNAUTHORIZED`。其它端 token 仍在，直到过期或被改密 / 重置 / 禁用吊销。

失败：未登录则为 401，而不是 200。

### 3.4 更改密码

前置：已登录。旧密码、新密码经现有 RSA 解密。本期不取消这条 RSA。

步骤：

1. 原密码不匹配：失败，不更改已存储的口令。
2. 新密码与原密码相同：失败。
3. 新密码不满足 2.3：失败。
4. 写入新的慢哈希，并把该用户的凭证版本加 1；这两步必须在同一次原子提交中完成，任一步失败则全部回滚。凭证版本是拟定机制（默认从 1 起，旧数据视为 1），具体方案另行设计。
5. 提交成功后吊销该用户的全部会话。若吊销失败：旧 token 仍须失败，因为校验时要比对会话中记录的凭证版本与用户当前凭证版本，不一致就拒绝。不允许「密码已改、旧 token 继续用」。

成功：无口令回显。通知见第 7 节，通知失败不回滚新口令。

要求达到的结果：签发会话时读取口令哈希及其对应的凭证版本，口令验证成功后再次核对版本，不允许拿旧哈希验证结果签发标记为新版本的会话；会话须记录该次已验证的凭证版本。每次鉴权与当前已生效的凭证版本比较，旧版本或无法可靠读取当前版本时拒绝。不能只依赖稍后才会失效的本地缓存。存量尚无版本信息的会话，在启用该门时统一吊销。改密提交与并发登录交错时，新签发会话若基于旧口令或旧版本，也必须被拒绝。

### 3.5 找回（拟新增，默认不上线）

本期不对外上线。以下为拟定接口与流程，实施仍取决于阶段与 D-RESET-PROOF，不得把「无证据也发信」当作可执行默认。

`POST /auth/password/forgot`

前置：找回开关未打开则接口不存在或返回未开放，二选一在实现时固定为「未部署」。邮箱格式合法。

步骤：

1. 规范化邮箱。按 IP 与邮箱限额（第 4 节）。
2. 只在第 2.5 节证据存在、且证据中的邮箱版本等于用户当前邮箱版本时，生成 6 位码。
3. 使用 HMAC-SHA256 保存验证码摘要，摘要须绑定用途、租户标识、用户标识、挑战标识、邮箱版本和验证码。附加密钥须由受控运行环境注入，不进入业务数据、日志或文档。禁止明文和裸 SHA-256；各输入采用确定且无歧义的编码，禁止直接拼接产生歧义。HMAC 用常量时间比较，随机码由成熟库的安全随机数生成器产生。
4. 邮件把验证码发给该地址。这是投递给用户，允许正文含验证码。日志和队列落地不得含明文码。
5. 无证据、无用户、或发信失败：不发可使用的码。

成功、没有可重置邮箱、渠道故障、邮箱额度或冷却命中对外相同，见 8.2。内部审计分开。投递异步执行，外部通用受理不代表已经送达；禁止把只有真实账号才会触发的发信失败码暴露出来。

`POST /auth/password/reset`

前置：body 带邮箱、`challengeId`、验证码、新口令。无 URL token。

步骤：

1. 按 4 节限制校验次数。
2. 验证码过期、已消费、或 HMAC 不对：同一失败，不说明是哪一种。
3. 同一挑战连续错 3 次：作废该 `challengeId`。之后再试仍是同一失败文案。
4. 通过后，须在同一次原子提交中完成：一次性消费该挑战、改口令并把凭证版本加 1。仅当挑战未消费、未过期、当前邮箱版本及 HMAC 均匹配时才能消费成功；并发下只允许一次成功，任一步失败则全部回滚。验证码错误次数和请求限流放在共享状态存储中，须单次原子更新。限流存储只负责次数与冷却，不承担与凭证存储之间的跨存储原子提交。限流、原子消费与凭证版本均为拟定机制，具体方案另行设计。
5. 提交后吊销全部会话。吊销失败时版本门仍拒绝旧 token。
6. 发「口令已重置」通知，正文不含验证码和口令。通知失败不回滚新口令，按第 7 节重试。

与注册链接的差别：找回不用 URL。注册秘密是否放在 fragment 见 D-LINK，该选择仍待确认。

## 4. 拟定参数

下表都是拟定，不是已配置，也不是已批准。与实现观察值的对照见 [现状分析](./auth_主PRD_现状分析.md)。

| 项 | 拟定 |
|----|------|
| 口令 | 8–32（UTF-16 代码单元）；至少包含一个小写字母和一个数字；特殊字符跟公开密码策略；UTF-8 字节大于 72 拒绝；BCrypt cost 10。详见 2.3 |
| 同账号口令 | 忽略大小写，口令不得等于用户名或邮箱本地部分 |
| 账号失败窗口 | 滚动 15 分钟。窗口内 5 次失败则锁定 15 分钟 |
| 锁定存储 | 失败记录按时间戳保存，在一次原子操作中移除 15 分钟前的记录后计数；失败记录的清理期限为最后一次失败后 15 分钟，仅用于清理，不能以清理期限替代滚动窗口。锁定标记在首次跨过阈值时设置 15 分钟有效期，后续请求不延长。锁定到期后同时清除旧失败记录，从零计数；成功登录或管理员解锁也清除该主体的失败记录及锁定标记 |
| IP | 每 IP 每分钟 30 次口令尝试，超过后该 IP 冷却 15 分钟。每 IP 每小时 200 次，超过后冷却 60 分钟。与账号锁定分开 |
| 不存在的标识 | 虚拟主体与真实主体同一状态机。HMAC 标识。锁定和要验证码两种响应，两种主体都能出现 |
| 图形验证码 | 只看该主体窗口内次数。满 2 次后要求。与账号是否存在无关 |
| 注册发送 | 重发间隔 60 秒，链接（若 D-LINK 选择链接方案）有效期 30 分钟。另加：每 IP 每小时 20 次、每日 50 次受理；每邮箱每日 5 次成功投递。失败立即重试每邮箱每小时最多 5 次。对外响应不得用冷却或投递结果做状态探测，见 D-EMAIL |
| 找回申请 | 每 IP 每小时 20 次。每邮箱每日 10 次。60 秒冷却。6 位，5 分钟，错 3 次作废 |
| 找回校验 | 每 `challengeId` 每 5 分钟最多 10 次校验请求，超出与验错同一失败文案 |
| 会话 | 首期不改这些数，沿用：绝对有效期 24 小时（86400 秒），空闲超时 30 分钟（1800 秒），有访问时刷新空闲计时；允许多端同时在线，每次登录签发独立会话；只从 `Authorization: Bearer` 读取会话，不靠 cookie。多实例必须共享会话与限流状态。无「记住我」，无 refresh |
| 通知重试 | 改密 / 重置通知：最多 3 次，间隔 1 分钟、5 分钟、15 分钟。不回滚已提交口令 |
| 时序验收 | 同一环境、同一标识长度，各 30 次「存在且口令错」与「不存在」。中位数之比不超过 1.5，且 p95 差值不超过 200 毫秒。这是门限，不是已测结果。允许抖动，但不接受数量级差异 |

以下原子性要求同为拟定机制，具体方案另行设计，但验收必须满足：失败计数须在一次不可分割的操作中完成「清除窗口外记录；追加本次失败；刷新清理期限；计数达到 5 时，仅在尚未锁定的情况下设置 15 分钟锁定」。禁止将计数、窗口清理、锁定拆成多个有竞态的请求。验证码的错误次数和请求限流放在共享状态存储中，须单次原子更新；有效挑战的 HMAC、用户标识与邮箱版本绑定、过期时间和消费状态，须与改口令、递增凭证版本在同一次原子提交中处理，且仅当挑战未消费、未过期、当前邮箱版本及摘要均匹配时才能消费成功，并发下只允许一次成功。禁止假定限流存储与凭证存储之间存在跨存储的天然原子事务。吊销失败不得使旧 token 继续可用。

## 5. 禁止

- 成功登录（以及将来明确的「会话交换」）响应可以把会话 token 发给已经证实的本人。除此以外，响应、日志、调试接口都不得出现口令、验证码、注册 token 原文或完整 JWT。
- 发给用户邮箱的注册链接或找回验证码，正文可以含那次凭证。这是投递，不是日志。改密成功、重置成功的通知不得含验证码或口令。
- 登录在口令未证实前：不存在、错密码、禁用，三者 HTTP 状态、业务 `code`、message 相同。禁用文案只在口令比较已经成功之后。锁定响应在比较口令之前返回，且虚拟主体也会进入锁定，因此不能靠「只有真账号才会锁定」来枚举。
- 图形验证码是否出现，只由该主体的尝试次数决定。
- 不承诺响应时间绝对常数。验收只用第 4 节的样本门限。
- 不自造口令哈希或 JWT 算法。低熵码的 HMAC 输入必须包含：用途、租户标识、用户标识（无用户则用稳定的虚拟标识，且该码不得升级成重置凭证）、`challengeId`、邮箱版本、验证码。缺任何一段都不能和别的用途或别的邮箱版本通用。
- 已登录且会话已有租户时，`X-Tenant-Id` 不能改数据租户，也不能代替成员校验。无租户的已登录调用，业务 API 默认拒绝。这是目标。
- 匿名登录不能在未决 D-LOGIN-TENANT 之前改成「一律租户 0」。否则租户管理员建在非 0 租户、且用户名或邮箱只在该租户唯一的账号会登不上。请求头不是授权；认证阶段仍要有受控的租户定位，定位之后再验凭证和成员。禁止为定位去扫全部租户的标识。

## 6. 安全能力与系统约束

认证须复用既有认证、用户与契约能力，不另起一套登录体系。口令使用成熟的慢哈希组件，不自造哈希算法，也不另做一套独立的登录拦截机制。

发信复用统一通知服务。找回首期不使用短信 OTP。

限流、锁定与会话状态必须存放在多实例共享的状态存储中。主体标识须绑定用途、租户与登录标识的不可逆摘要。附加摘要密钥与会话签发密钥须由受控运行环境注入，与业务数据隔离，不进入业务存储、代码、日志或文档。共享状态存储不可用时，登录与找回拒绝。注册对外按第 3.1 节与 D-EMAIL 统一受理，不把投递失败作为对外可区分结果；内部审计记录原因。

租户定位与授权分开：

- 公开注册可以固定在一个受控入口租户。这只决定新账号写到哪，不表示该请求被授权读该租户业务数据。
- 匿名登录的租户定位必须是可验证的上下文，并且能覆盖已经存在的非 0 租户账号。同名出现在多个租户时，不得靠遍历全部租户的标识挑一个。定位方式未决，见 D-LOGIN-TENANT。在此之前维持既有租户定位，避免首期改坏现有登录。
- 定位完成后，口令校验只在该租户内进行。通过后再做成员与权限。已登录请求的后续数据租户以会话为准。

## 7. 审计与通知

登录审计中的用户名字段长度至少与用户名允许长度（64）对齐；未对齐前不得把长用户名登录审计写失败当成可接受结果。P1 包含此项。

审计最小字段（事件不同可以空着，不重复发明字段）：请求 ID、时间、可信来源 IP（代理跳数只信运维配置）、UA 的截断值（最多 256 字符）、主体 HMAC、结果、内部原因、租户标识。禁止口令、验证码、注册 token、完整 JWT。

| 事件 | 内部原因示例 |
|------|----------------|
| 登录成功 / 失败 | `NO_SUCH_IDENTIFIER`、`PASSWORD_MISMATCH`、`LOCKED`、`DISABLED_AFTER_PASSWORD` |
| 锁定 / 解锁 | `THRESHOLD`、`TTL_EXPIRED`、`ADMIN_CLEAR` |
| 强制下线 | `DISABLE`、`ADMIN_KICK`、`PASSWORD_CHANGED` |
| 重置申请 / 成功 / 失败 | `NO_PROOF`、`MAIL_FAILED`、`CODE_MISMATCH`、`CONSUMED` |
| 注册受理 / 发信失败 / 确认 | `MAIL_FAILED`、`LINK_INVALID` |

查询登录日志保持现有监控权限。租户管理员不能下载其它租户的认证审计。保留天数沿用登录日志配置 365 天。

通知中文模板（占位，无秘密）：

- 改密成功：「你的登录口令已更改。如果不是你本人操作，请尽快联系管理员。」
- 重置成功：「你的登录口令已通过邮箱验证重置。如果不是你本人操作，请尽快联系管理员。」
- 若 D-LINK 选择链接方案，注册邮件维持「请打开链接并在页面上确认」的说明，链接有效分钟数用配置值。找回邮件若上线，只写：「你的验证码是 {code}，5 分钟内有效。」

普通发件记录不得持久化明文验证码或注册 token。若投递队列必须暂存正文，敏感载荷使用 AES 加密存储，有效期不超过该凭证有效期，仅授权的发信服务可以解密消费；具体密钥组织与托管方式由技术方案定义。改密通知的队列正文本来就没有验证码。

## 8. 接口

下文「HTTP」和「业务 code」分开写。除 D-EMAIL 已确认的注册统一受理外，目标码是拟定，不是已实施。未登录访问需登录接口：HTTP 401，`code` 为 `UNAUTHORIZED`。业务认证失败默认 HTTP 422，body 为既有统一业务响应形态（含业务 `code` 与 message）。

### 8.1 既有接口的目标契约

`GET /auth/register/options`，匿名。

响应 200，字段：`enabled`，口令 `minLength`、`maxLength`，`requireLowercase`，`requireDigit`，`requireSpecial`，`verificationTtlMinutes`，`resendIntervalSeconds`。无角色 id。拟定不另加登录失败那种锁定。

`POST /auth/register`，匿名。请求：`email`、`password`。目标按已确认 D-EMAIL：合法请求在邮箱可受理、已注册、无待验证申请、邮箱冷却或额度命中、邮件投递失败这些分支，统一返回 HTTP 200、`code=200`、`status=ACCEPTED`，文案「注册申请已受理。如该邮箱可用于注册，你将收到验证邮件。」不返回 token，不含可用于探测的 `delivered` / `PENDING` / `COOLDOWN`。限流用第 4 节注册发送额度。参数格式错误、注册整体关闭、账号查找前统一执行的 IP 限流可返回明确错误，但同一条件不能因邮箱存在与否而改变响应。

`POST /auth/register/resend`，匿名。请求：邮箱。未在本文写明的字段名不另猜测，沿用既有对外字段。目标按已确认 D-EMAIL，与注册使用同一种统一受理形态，不返回可区分邮箱状态的错误、投递结果或冷却差异。

`POST /auth/register/verify`，匿名。请求：`token`（若 D-LINK 另选验证码方案，再按该决定调整请求字段；未确认前不提前改链接形态）。成功：HTTP 200，`code=200` 与 `status`（`VERIFIED` 或 `ALREADY_VERIFIED`）。无登录 token。失败：HTTP 422，`REGISTER_LINK_INVALID`，message「链接无效或已过期」。过期、空、找不到都用这一句。

`POST /auth/login?grantType=PASSWORD`，匿名。请求必填 `clientId`；`username`、`email`、`phone` 三选一；`password`；需要图形验证码时加 `captchaUuid`、`captchaChallenge`。成功：HTTP 200，`code=200`，`token` 为会话凭证。这是第 5 节的唯一必要例外。失败目标：不存在、错密码、口令未证实的禁用，都是 HTTP 422，业务 `code=AUTH_FAILED`，message「账号或密码错误」。内部原因只进审计。锁定为 HTTP 422，`code=AUTH_LOCKED`，message「尝试过于频繁，请稍后再试」，真实主体与虚拟主体相同。需要图形验证码：HTTP 422，`code=NEED_CAPTCHA`，message「需要验证码」，只由计数触发。口令已证实后的禁用：HTTP 422，`code=AUTH_ACCOUNT_DISABLED`，message「此账号已被禁用，如有疑问，请联系管理员」。

`POST /auth/logout`，要登录。成功：空。旧 token 再请求为 HTTP 401。

`GET /auth/user`，要登录。返回资料、角色码、权限码、菜单。无租户时的目标是不把它变成读取租户 0 业务数据的口子；菜单按会话租户过滤。

`GET /captcha`，匿名。返回图形验证码载荷。不返回口令相关数据。

`PATCH /user/profile/password`，要登录。请求含旧密码、新密码（RSA 密文，字段名沿用既有对外字段）。成功空 body。失败：原密码错、新旧相同、不符合口令门，均为 HTTP 422，业务码沿用既有口令错误类，不新增会区分「用户在不在」的码。

`GET /oauth/{provider}` 与 `POST auth/otp` 本期不改契约。OTP 既有限流不作为找回的限额。

### 8.2 拟新增

`POST /auth/password/forgot`。请求：`email`。成功与「无验证证据 / 无此邮箱 / 发信失败 / 邮箱额度或冷却命中」相同：HTTP 200，`code=200`，`status=ACCEPTED`，message「如果该账号存在且已验证邮箱，将发送验证码」，返回不透明 `challengeId`，不含验证码或 delivered 字段。不发信的分支也返回同长度、同格式的随机 challengeId，该虚拟挑战永远不能重置密码；这不意味着为未知账号生成可用验证码。异步投递结果和失败原因仅进内部审计。IP 级限流在查账号前对所有标识一致返回 HTTP 429，`code=TOO_MANY_REQUESTS`，不根据邮箱是否存在分叉。限流见第 4 节。

`POST /auth/password/reset`。请求：`email`，`challengeId`，`code`，`newPassword`。成功：HTTP 200，`code=200`，无 token。失败（过期、已用、错误、超次数）：HTTP 422，`code=AUTH_FAILED`，message「验证码错误」。新口令不合格：HTTP 422，口令格式类错误，不带验证码。

### 8.3 无租户已登录的最小允许列表（目标）

这道限制作用在身份认证成功后、访问业务资源前，且仅当已登录但会话尚无租户时生效。未登录请求不走这道拒绝，因此登录、注册、验证码、静态资源以及既有匿名可达路径不会被它拦住。

允许（方法 + 路径）：

| 方法与路径 | 原因 |
|------------|------|
| `POST /auth/logout` | 退出 |
| `GET /auth/user` | 登录后需要拉取当前用户资料 |
| `GET /org/session` | 看自己有没有租户 |
| `GET /org/invites/preview` | 打开邀请。该路径对未登录访问仍保持既有匿名可达 |
| `POST /org/invites/accept` | 接受邀请 |
| `POST /org/invites/reject` | 拒绝邀请 |
| `POST /org/applications` | 申请加入。业务开关仍可拒绝 |
| `POST /org` | 创建租户。业务开关仍可拒绝 |

不在表内的受保护接口，对无租户登录会话默认 HTTP 403，body `code=403`，message「您当前没有访问该租户的权限」。包括 `POST /org/switch`、`POST /org/invites`、`POST /org/applications/{id}/review`、用户列表、字典、菜单管理。验收时遍历全部受保护接口，而不是只测这八行。新增受保护接口默认拒绝。

## 9. 场景

以下都要准备数据后才能测。本需求文档不代替实现交付中的验收执行。

正常：

1. Given 注册开放且邮箱无账号。When 提交合法邮箱和符合 8–32 的口令。Then HTTP 200、`code=200`、`status=ACCEPTED`，无 token，不出现 `delivered` / `PENDING` / `COOLDOWN` 探测字段；若该申请实际进入待验证，待验证申请只保存哈希，不保存口令或 token 原文。若 D-LINK 选择 fragment 方案，则实际发出的邮件含 fragment，且不把 token 放进 URL 查询串。
2. Given 一条未消费且未过期的有效确认秘密（若 D-LINK 选择 fragment 方案，即该注册 token）。When POST 确认。Then 一个可登录用户，该申请被标记为已消费，响应无登录 token。
3. Given 该用户且定位到其所在租户。When 用邮箱和同一口令登录。Then HTTP 200，body 含 token。另一端再登录得到另一枚 token。
4. Given 已登录。When 退出。Then 该 token 再访问为 HTTP 401。

攻击与失败（每条可单独做）：

1. Given 某主体（可以是不存在的标识）在 15 分钟内已失败 5 次。When 立刻提交正确口令或任意口令。Then 都是 `AUTH_LOCKED`，且实现上在返回前不再按「对错」分叉。锁定到期后正确口令可以登录。
2. Given 标识不存在、口令错误、账号禁用但口令错误。When 各登录一次。Then HTTP 422，`code` 与 message 三者相同。
3. Given 禁用账号且口令正确。When 登录。Then 才是 `AUTH_ACCOUNT_DISABLED`。
4. Given 两台实例共用同一共享状态存储。When A 把主体加到锁定。Then B 的下一次尝试也是锁定。
5. Given 图形验证码门只差一次。When 对不存在的标识再失败一次。Then 下一次返回 `NEED_CAPTCHA`，与真实账号相同。
6. Given 注册确认秘密已消费或已过期。When 再确认。Then 已消费不建第二个用户；过期文案与随机无效秘密相同。
7. Given 找回验证码已过期、已消费、或连续错 3 次。When 再提交。Then 都是 `AUTH_FAILED` / 「验证码错误」。
8. Given 找回冷却 60 秒未到。When 再次申请。Then 不新发一枚仍有效的码，对外仍是受理成功，不另给「发送太快」的存在性提示。
9. Given 两个并发重置用同一枚正确验证码。Then 只有一个请求改口令成功，另一枚消费失败。
10. Given 重置或改密已成功提交。When 旧口令登录，或使用改密前签发的任一 token。Then 旧口令失败；旧 token 即使会话吊销没成功也被版本门拒绝。本条以第 3.4 节拟定版本门为前提。
11. Given 改密时原密码错误，或新密码与原密码相同。Then 口令不变，会话仍在。
12. Given 用户被禁用且持有旧 token。When 调用需登录接口。Then HTTP 401。
13. Given 同一邮箱并发注册。Then 最多一个可登录用户，未消费的待验证申请最多一条。
14. Given 邮箱没有第 2.5 节证据（含后台建号、只改了邮箱值）。When 申请找回。Then 不发信，对外与有证据且受理成功相同。本条以 D-RESET-PROOF 接受这道门且找回进入实施为前提，不是把未决项当成已批准。
15. Given 重置邮件发送抛错，且当时存在证据。Then 外部仍为通用 ACCEPTED 且不含 delivered，后台记录投递失败，挑战不得变为可用。Given 口令已经改成功而通知抛错。Then 口令保持新值，通知进入重试，日志无验证码。
16. Given 已登录且会话租户为 A。When 请求头写成 B。Then 数据租户仍是 A。Given 非 0 租户中已有用户名只在该租户唯一。When 在 D-LOGIN-TENANT 未决时按既有租户定位登录。Then 不因本文首期被强制改到租户 0 而失败。Given 已登录但无租户。When `GET /system/user`。Then 目标 HTTP 403。
17. Given 口令 7 个字符、33 个字符、或 UTF-8 超过 72 字节。Then 都拒绝且不得存入口令哈希。32 个符合字符门且字节不超过 72 的口令可以注册。
18. Given 口令忽略大小写后等于用户名或邮箱本地部分。Then 拒绝。
19. Given 成功登录响应。Then body 可以有 token。Given 同一次的日志、找回响应、注册响应、改密通知。Then 没有口令、验证码、注册 token 原文或第二份 JWT。
20. Given 验证码 HMAC 用了另一个用途、另一个租户标识、另一个用户标识、另一个 `challengeId` 或旧邮箱版本。When 拿去重置。Then 失败。

### 9.2 邮箱注册统一受理验收（D-EMAIL 已确认）

Given 合法格式邮箱分别处于未注册、已注册、无待验证申请、重发冷却、邮箱额度耗尽及邮件投递失败状态。When 在相同公开开关和 IP 限额条件下提交注册或重发。Then 均返回相同 HTTP 200、`code=200`、`status=ACCEPTED`、文案及字段形态，不出现邮箱占用或投递结果，也不出现 `delivered` / `PENDING` / `COOLDOWN` 探测差异；实际发送与建号仍按业务约束执行，内部审计可以区分。When 对比响应耗时。Then 不得因同步发送或直接短路暴露邮箱状态，并按第 4 节同环境样本门限验收。Given 管理端创建用户名重复。Then 仍提示「用户名已被占用」。

### 9.3 并发发会话补充验收

Given 登录已读到旧口令哈希与版本 v，且改密或重置并发提交为 v+1。When 该登录继续签发会话。Then 不得把旧口令验证结果包装成 v+1；即使生成了标记为 v 的 token，第一次访问也被版本门拒绝。本条以第 3.4 节拟定版本门为前提。Given 通知服务故障且不存在/存在两类邮箱分别申请找回。Then 二者状态码、字段形态、文案一致，不能通过投递失败反推邮箱是否存在。

## 10. 决策与阶段

### 10.1 已确认与未决

#### 已确认：D-EMAIL（2026-11-19，非洲/金沙萨）

用户确认：「邮箱注册采用统一受理提示，不暴露邮箱是否已注册；用户名重名仍按原决定明确提示。」

- 公开注册与重发：合法请求在邮箱可受理、已注册、无待验证申请、邮箱冷却或额度命中、邮件投递失败这些分支，统一返回 HTTP 200、`code=200`、`status=ACCEPTED`，文案「注册申请已受理。如该邮箱可用于注册，你将收到验证邮件。」不返回 token。
- 禁止通过 `EMAIL_EXISTS`、`REGISTER_NOTHING_TO_RESEND`、`REGISTER_MAIL_UNSENT`、`delivered`、`PENDING/COOLDOWN` 差异或仅部分邮箱分支出现的剩余时间暴露状态。`resendAfterSeconds`、`expiresMinutes` 如前端必须使用，按公开策略给固定值，不返回真实记录剩余时间。
- 投递异步完成；内部仍分别记录重名、冷却、额度与投递失败原因。响应时序也纳入防枚举验收，不能只统一文案。统一受理不表示邮件已经发出或账户已经建立，也不允许向已注册邮箱重复创建用户或绕过原有发信限额。
- 参数格式错误、注册整体关闭、账号查找前统一执行的 IP 限流可返回明确错误，但同一条件不能因邮箱存在与否而改变响应。
- 用户名重复继续明确提示「用户名已被占用」，不将邮箱防枚举规则扩展成对既有 R4 的撤销。

此处只更新需求决定。文档确认不等于已经实施或授权开工，也不代表其余未决项或拟定方案已批准。

### 10.4 以后可收进 conventions 的句子

还不是仓库规范：

- 口令未证实前，认证失败的 HTTP 状态、业务 `code` 和 message 不得区分标识是否存在；锁定和验证码门对虚拟主体同样生效。
- 口令只存成熟慢哈希组件的结果；禁止截断后哈希；UTF-8 超过 72 字节拒绝。
- 低熵验证码只存带用途、租户、用户、挑战、邮箱版本的 HMAC。
- 成功认证响应可以向本人签发会话 token；其它响应和日志不得携带该凭证。投递给用户的邮件可以含当次验证码；变更通知不得含验证码。
- 已登录后的数据租户以会话为准。请求头不能授权。匿名登录的租户定位不得遍历全部租户的标识。

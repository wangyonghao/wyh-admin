# wyh-admin — Mission

## Purpose

wyh-admin 是一套经实践沉淀、可二开的 **B 端工程底座**——不是再堆一个功能大全模板。

它要解决的问题是：没有规范约束时，项目一久就积重难返。底座要赢的是「越做越干净」：分层清晰、代码健康、长期演进不腐化；在此之上提供稳定可靠、够用的通用中后台能力。

愿景：先把自己用爽、用稳；再以开源与协作沉淀实践，让人和 AI Agent 都能在清晰规范下持续扩展。

## Users

按优先级：

1. **项目所有者本人** — 第一用户；工作 / 侧项目直接二开，底座首先服务自己。
2. **后端 / 全栈开发者** — 需要可扩展、规范清晰的脚手架，快速开工专属中后台。
3. **AI Agent 使用者** — 依赖仓库内规范与规格，驱动 Agent 持续改代码而不漂移。
4. **开源社区与小团队** — 次要；在自用扎实之后，再服务贡献者与交付协作。

## Solution

提供前后端一体的模块化单体中后台：多租户 / 组织、RBAC 与数据权限、用户 / 角色 / 菜单 / 部门、消息与公告、文件、字典与系统配置、任务调度等，形成稳定够用的业务闭环；同时通过清晰分层与工程规范，支撑人与 AI 长期协作扩展，避免积重难返。

## Differentiators

相对常见开源 Admin（如 RuoYi、ContiNew、yudao）的站位：

- **不拼功能广度**：yudao 等功能已较全面；wyh-admin 追求稳定可靠、够用，不做厨房水槽式堆砌。
- **不做独立 starter 全家桶**：ContiNew 前端用心，但后端独立 starter 过碎、维护成本高；wyh-admin 坚持模块化单体内的清晰分层。
- **不拼工程师味的功能堆砌**：RuoYi 前端偏工程交付感、交互一般；wyh-admin 要把第一印象做成沉稳、工匠级的 UI 与交互。
- **规范可扛住长期演进**：痛点是缺规范导致腐化；底座把分层与代码健康写进仓库，越做越干净。
- **可二开的实践底座**：先服务自己，经真实使用沉淀，再谈开源与团队。

## Success

12 个月内的最低成功标准：

1. **真实可用的演示站点** — 访客可直接体验，第一眼感受到沉稳、工匠级 UI/交互，功能稳定可靠、够用。
2. **项目文档站点** — 可跟人、可跟规范、可二开。
3. **成熟的功能模块** — 通用能力闭环，足以支撑专属中后台落地。

日常仍同时满足：克隆可本地跑通；扩展时人与 AI 保持架构一致、避免腐化。

## Non-goals

- **不追求微服务拆分**：保持模块化单体（或等价的清晰模块边界）优先；不为拆服务而拆服务。
- **不做独立 starter 全家桶**：不引入碎裂的独立 starter 体系增加维护成本。
- **不与竞品拼功能清单广度**：功能以稳定够用为准，不以「别人有我们也有」为目标。

## Current focus

按优先级推进：

1. **打磨开源脚手架体验与规范** — 稳定、舒适、可交付；UI/交互向沉稳工匠级靠拢。
2. **强化 AI 友好** — 规范、规格与可生成性，降低 Agent 协作成本与漂移风险。
3. **完成 platform 领域重构与分层治理** — 持续收敛领域边界与模块职责。
